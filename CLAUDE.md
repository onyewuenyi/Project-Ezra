## What this is

**Project Ezra** ("Managing Chaos, Effortlessly") — an AI-managed household task system for iOS. SwiftUI + Core Data, single app target. **The product spec is not in this repo:** *Ezra Product Shape v8* (https://claude.ai/code/artifact/aa4e89a0-a1ff-4ed2-b0f8-c6e227ed7014) is the source of truth for what the product is and what the MVP cuts; where any file here disagrees with it, the artifact wins. **Kinly** is the launch positioning layered over v8 (`docs/kinly-launch-plan.md`) — not a rename (the name stays Ezra until the App Store/trademark check) and not a new spec.

The repo keeps architecture and craft: `docs/README.md` (the map) · `docs/task-model.md` (the four axes) · `docs/primitives.md` (the durable core + the bloat-watch test) · `docs/capture.md` · `docs/advisor.md` · `docs/surfaces.md` · `docs/platform-notes.md` · `docs/decisions.md` · `docs/cohort0-checklist.md` · `prev-docs/design-system-managing-chaos.md` · `prev-docs/product-guardrails.md` · `prev-docs/household-architecture.md`.

## Posture — research preview, on purpose

Single-developer R&D build, deliberately on the newest software (iOS 27 GA from 2026-09-17 — Xcode 27.0, macOS 27.0, Foundation Models year-two APIs, Firebase's public-preview `GeminiLanguageModel`; it was betas and a branch pin before that). Do not gate a capability on evidence that does not exist yet — turn it on, then measure (evals *tune* what runs, never grant permission). No "wait for GA" caveats. Do not soften a capability without being asked. Two things this never relaxes: **safe defaults for data** (the deterministic tail always exists, `validated(against:)` rejects untrusted model output, corrections never leave the device) and **the guardrails** (`prev-docs/product-guardrails.md`).

## Build, run, test

```bash
# Build (iOS 27 simulator)
xcodebuild -project Project-Ezra.xcodeproj -scheme Project-Ezra \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=27.0' -configuration Debug build

# Tests (Swift Testing). -parallel-testing-enabled NO is REQUIRED: fixtures share one
# in-memory context (PersistenceStack.scratch / TestStore) with thread affinity.
xcodebuild test -project Project-Ezra.xcodeproj -scheme Project-Ezra \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=27.0' \
  -parallel-testing-enabled NO
```

**Two scripts carry the submission (2026-09-20):** `scripts/submit.sh` archives, audits the built bundle, exports with `method: app-store-connect` and validates — stopping at the first thing only a human can fix (no Apple Distribution certificate, no privacy-policy URL) and saying what to do about it, because `xcodebuild archive` succeeding proves nothing about submission. `--internal` (2026-09-30) skips ONLY the privacy-URL gate, for internal TestFlight; every run audits the EXPORTED signature (`aps-environment` production, the iCloud container, no `get-task-allow`) and prints the version and build — bump `CURRENT_PROJECT_VERSION` before every upload after the first. `scripts/screenshots.sh` drives the DEBUG seams to produce the required 6.9" iPhone and 13" iPad sets from one seeded store, with a per-shot wait and a 9:41 status bar. Both pick the simulator by NAME AND RUNTIME — the machine carries several, and a name-only match grabbed an iOS 26.3 device whose install then failed on the deployment target.

Prefer `/run-sim` for install + launch + screenshot. A clean build is sufficient to call a change done. Tests live in `Project-EzraTests/` (`@testable import Project_Ezra`) and cover the pure AI/ranking logic — add cases there when you touch it. **Known flake (2):** `CaptureHedgeTests.totalBudgetIsSpentOnce` asserts a 0.6s budget and FAILS when the machine is loaded — a simulator driving screenshots beside the run is enough; rerun with the sim idle before believing it. **Known flake:** every case green but the run ends `TEST FAILED` via `Restarting after unexpected exit` with zero Core Data exceptions — the Xcode 27 beta sim's accessibility-bundle conflict; re-run. A run with `✘` cases or an `NSInvalidArgumentException` is real.

## Project layout & Xcode gotcha

- `Project-Ezra/` is a **PBXFileSystemSynchronizedRootGroup**: create or delete `.swift` files and they compile; **never hand-edit `project.pbxproj` for files** (build settings and SPM packages only — the Firebase and Statsig entries are hand-authored and the pattern to copy).
- Feature-organised: `Design/` · `Models/` (Core Data models, `PersistenceStack`, pure ranking) · `AI/` (engines, seams, evals) · `Features/<Screen>/` · `Features/Components/` · `Intents/`. The task model is `Models/TaskItem.swift`; models are built with the `in:` context inits.
- Three seams to know before reinventing one: **`AI/SerialGate.swift`** (one-at-a-time execution; the stored task wraps the WORK, not the wait; `peakActive` for tests), **`AI/CaptureProvenance.swift`** (per-capture receipt as a JSON file sidecar via `Models/Sidecar.swift` — *a diagnostic must never be able to cost the user their data*; every diagnostic follows), **`AI/DeterministicReading.swift`** (rung 0's Advisor reading).
- **Swift-format** runs on every edited `.swift` via a PostToolUse hook (`.swift-format`: 4-space, 110 col). Don't hand-align.

## Rules — task model (`docs/task-model.md`)

- **Four axes, never fused.** (1) Lifecycle `TaskStatus` (`.todo → .doing → .done | .canceled`), user-owned; a `TaskItem` exists at Confirm and never before (pre-Confirm state is a parked `Capture`; `AppBrain.commit` IS the confirm; `status.isLive`). (2) Type `WorkIntent` (action/planning) — INTERNAL, system-owned, never a chip, never user-edited, never nil at creation (`IntentResolver.inferredWorkIntent` backfills, and never reads `isJudgmentCall`/`needsDecision`); retired cases decode additively. (3) Attention flags — `needsDecision` stored; Blocked/Blocking/Overdue/Stale derived on read. (4) Signals — `isUrgent` human-declared feeding a persisted 0–100 score (`AttentionEngine` → `AttentionMetadata`) that only breaks ties within bands; never a badge; reads slow inputs only. Adding a blocker must not move status; confidence must not auto-resolve a judgment call.
- **Judgment calls are a permanent carve-out:** always `.ask` tier (`AutonomyPolicy.tier`), `needsDecision` from birth, only `resolveDecision()` clears it; `BrainSweeps` never touches one; `autonomy` is derived, not stored.
- **Every status change goes through `TaskItem.status`'s setter** (`transition(to:now:)` records the `StateVisit` timeline and bumps `updatedAt`). Never write `statusRaw`; never expose `$task.status`; **every mutation helper bumps `updatedAt`**.
- **Blocked is derived, never written** (`activeBlockers(among:)`); no `block()`. Edges live in one versioned `relationshipsData` blob (`Models/Relationship.swift`, kinds `.blocks/.parent/.related`, each with an `Origin`); `blockers`/`parentTaskID` are read-only views; **every write goes through `TaskMutations`**. A rejected suggestion is a `RelationshipSuppression`, never a dismissed edge. The umbrella-before-steps fact is DERIVED (`openSteps`/`stepProgress`), never a stored wait; `splitInto` writes one edge per step ON the step; `TaskChainGrouping.prerequisites(of:within:)` is the ONLY place the two graphs meet. Display order of steps IS `sortIndex`; `children(among:)` is the one ordered derivation.
- **The row's leading marker is one slot with two residents** (`SignalMarker`: Needs Decision wins over Urgent; never the type). **The primary CTA is one slot or none** (`RecommendedAction`: resolved → Reopen · unowned → That's mine · someone else's → **nil, by design** · blocked → Unblock · `.todo` → Start · `.doing` → Mark done). The verb never voices the type — one view-layer carve-out: on a `.deciding` page `.start` reads "Decide". Start relabels in place; only `.resolve` dismisses. **List gestures, one meaning each:** tap opens detail; leading swipe = `performRecommendedAction` (absent when nil); trailing swipe cancels (absent on resolved); long-press = menu. The glyph's status menu is retired. Never a second button under the CTA.
- **Stack precedence** (`Models/TaskRanking.swift`): Needs Decision top → Blocked sinks → effective attention desc → Blocking → Overdue, as lexicographic keys (strict weak ordering, property-tested). The ONE additive layer is `attention.score + currentRelevance` (live, clamped ±25): staleness pulls down (from `lastHumanTouchAt`, consecutive and cleared by `touchHuman`); unblock/dependent/due/`startedBoost` (current open `.doing` visit only) pull up. **`.doing` may touch this layer and no other.** Precomputed once per snapshot into `RankKey`, never inside the comparator. The deferral pull-down is DELETED, not repointed (an abandoned start is the opposite of a soft "not today").
- **Ownership: every task is born owned.** `OwnerProposer` is total and deterministic (spoken → adjacency via `childOf`/`duplicateOf`, never blockers → affinity → the capturer); "unowned" is exactly `ownerID == nil` and only a human hand-back produces it; load adjusts, never selects. `.defaultSelf` carries no reason and no ✦. `ownerOrigin` (`.human`/`.inferred`) is stored because the affinity denominator counts human ownership only. `creatorID` is authorship.
- **Confirm is the single publish boundary** (`AppBrain.publishAssignments`); assignment side effects bind to it, never to the owner field. Target behaviour is *notified*; the interim is a silent publish.
- **Undo-completeness:** a `ChangeLogUndo` arm restores every field its action wrote (e.g. `"assigned"` encodes `"<uuid>|<origin>"`). `ChangeLogEntry` backs Undo and the trail; `initiatedBy` separates AI from human; `Metrics.acceptanceRate` counts AI entries only, excluding `"planned"`.

## Rules — sync, persistence, schema

- **`HouseholdSync.isLive` is `true` (2026-09-12)**, flipped as ONE act with `PersistenceStack.cloudKitContainerID` (`iCloud.amanze-studios.Project-Ezra`), the entitlement and `CKSharingSupported` (`SyncGateTests.gateIsOpenAsOneAct`). The `Household` is the root of a `CKShare` in the owner's private database; model v4 gave `TaskItem` and `ChangeLogEntry` a `household` edge so the plan and trail ride the share; `Correction`, `Capture`, `EmbeddingCache`, `SuppressionRecord`, `UserProfile` have no edge and never travel. Two stores in one `NSPersistentCloudKitContainer` (private, then shared); **`HouseholdStoreAffinity` decides the store once, at save, for every creation site** — never assign a store at a creation site. `Household.existing(in:)` prefers the largest roster. The unit-test host never constructs the CloudKit container (`usesCloudKit`).
- **The App Store privacy manifest is `Project-Ezra/PrivacyInfo.xcprivacy`** (2026-09-18) and must agree with `Models/DataBoundary.swift` — no tracking, three unlinked collected types (product interaction · the anonymous install id · a capture's raw words), one required-reason API (`UserDefaults`, CA92.1). Verify it ships in the BUILT bundle in both configurations, not just that the file exists.
- **A sharing failure speaks the product's words** (`HouseholdSharingError.naming`, 2026-09-18): the account, network and storage codes map to sentences a person can act on; an unmet code still surfaces raw rather than be disguised. Both halves — the inviting phone and the arriving one.
- **The invite is one link** (`Features/Household/HouseholdSharing.swift`): the share URL with public read-write permission plus an `Invitation` naming the member; `SceneDelegate` receives the tap; identity links without asking only when exactly one invitation is pending, otherwise `IdentityLinkSheet` asks — never guessed from a name. Every stage is a `TelemetryInviteStage`. The simulator proves none of the CloudKit half; the two-phone sitting is in `TODO.md`.
- **`schemaGeneration` is FROZEN at 10** (`Project_EzraApp.frozenSchemaGeneration`, `SchemaFreezeTests` reads the compiled `.mom`s). Every model change is a NEW `.xcdatamodel` version that is a superset of the last — nothing removed, no type changed, optional→required forbidden, every attribute optional or defaulted, every relationship inverse-paired. A meaning change is a new field beside the old. **Never edit the current model version in place** (Editor ▸ Add Model Version; hand-authoring the directory works); the DEBUG digest tripwire tells the safe act from the mistake by membership in `bundledModelVersionDigests`. Current: `ProjectEzra 4.xcdatamodel`.
- **Every reset takes a safety copy first and is reported**: `PersistenceStack.destroyStore(reason:)` backs up both stores' sqlite + `-wal` + `-shm` (last 5), writes a `StoreResetRecord` Settings leads with, no in-app restore. `DataExport` is the readable JSON snapshot. Never touch `PersistenceStack.scratch`'s objects en masse.
- **A bulk delete happens in the STORE, and the interface is REBUILT, never refreshed (2026-09-19).** "Clear all tasks" and "Reset everything" crashed with SIGSEGV every time, from `SettingsView`, which holds live `@FetchRequest`s for the entities it deletes. The fault is teardown-after-read — the same one the test host has worked around since 2026-08-07 (`TestStore`): once an object's attributes have been read, ANY later teardown of it dies in `objc_retain` on a value that is no longer a pointer. Three teardowns reach this path and all three were measured crashing: the per-object `context.delete` loop (0/6), `mergeChanges(fromRemoteContextSave:)` — which calls `deleteObject:` on every match, named by lldb — and `refreshAllObjects()` (1/6); `reset()` made it deterministic AND invalidated the identity objects Settings is bound to. So: delete with `NSBatchDeleteRequest` (persistent history tracking is what lets CloudKit export it), tell the live context NOTHING, park `context.registeredObjects` for the life of the process so nothing deallocates either, and close the gap the silence leaves — a batch delete posts no change, so every `@FetchRequest` on screen keeps listing rows that are gone (measured: store empty, list showing ten tasks) — by bumping `DataGeneration.shared.rebuild()`, one counter the root view's `.id` keys on. Bumped on Settings' `.onDisappear`, after the receipt is read, never mid-flow. Every view deriving from a `FetchedResults` a destructive path can empty filters `isLiveRow` (`Models/LiveRow.swift`). `ClearRebuildTests` pins the forbidden calls by grep, because the property is the absence of one. **Measure a destructive path with a plain-launch guard in the loop:** this simulator's runtime breaks on its own (`dyld: Library not loaded: /usr/lib/libSystem.B.dylib`, fixed by `simctl shutdown` + `boot`) and a broken runtime reads exactly like an app crash — it invalidated three measurement batches before the guard existed.
- **The launch self-heal repairs ONE store, never both (2026-09-20).** `loadPersistentStores` runs its handler once per store description, and the heal destroyed every store file in the container and reloaded the lot — so a CloudKit shared mirror that would not open took the private store with it, and the private store is every task the person ever captured. `destroyStore(only:)` now removes just the named file (both are still COPIED; a wider net is never wrong on a path that deletes), the failed description alone is re-added, and only the PRIVATE store keeps its `fatalError` — a shared mirror that will not open is a launch without sync, which the code already handles, not a crash. `StoreBackupTests` pins both arms.
- **Sync has a meter (`Models/SyncHealth.swift`, 2026-09-20).** `NSPersistentCloudKitContainer` degrades in total silence, and the only listener kept one successful import and discarded every failure — so a container that had never once exported a record read exactly like one with nothing to send. The same shape that left `EmbeddingStore` off for a month. Folds `eventChangedNotification` into setup/import/export stages, keeps a stable `CKError.<code>` label never a message, and reports the WORST stage as the headline so a working import cannot hide a failing export. `.noAccount` and `.offline` are conditions, not faults. **`.schemaMissing` is the launch-day failure, named:** a distribution build talks to the container's Production environment, where the schema does not exist until someone deploys it (`TODO.md`), so every export fails on day one with no symptom. DEBUG-surfaced only — "sync is broken" on a customer screen is a thing to manage (principle 10); the one place a person needs a sentence is Invite, which `HouseholdSharingError.naming` owns.
- **The participant's phone is a first-class place (2026-09-30).** A household in the shared mirror wins `Household.existing` outright (`preferred(among:isShared:)`, `PersistenceStack.isShared` reads the file name); `bootstrapIdentity` honours `linkedMemberID` in ANY household and mints a fresh "You" only in the install's OWN (`Household.own`); "awaiting a link" is DERIVED (`HouseholdSharing.needsLink`), the chooser asks only with candidates and keeps its id; **a clear never touches the shared mirror** (`DataReset.clearableStores`); the roster shows one household's members and invites only where `canShare`. Every "you" read uses `UserProfile.chosenOrder` (grep-pinned). Sync failures log to Console.app (`category: sync`) — a TestFlight phone has no DEBUG card. Open: a participant's pre-join tasks stay under their pre-join member.
- **Every `saveChanges()` result is checked** — a dropped save must leave a trace.
- **Export compliance is answered in the binary** (`ITSAppUsesNonExemptEncryption` false, honest — no CryptoKit/CommonCrypto/keychain crypto, only HTTPS): without it App Store Connect stops every upload and TestFlight will not distribute. `SubmissionGateTests` pins it alongside the microphone reason and the manifest's three unlinked types.
- **`FirebaseApp.configure()` runs only when there is a plist to configure from.** `GoogleService-Info.plist` is gitignored and `configure()` raises an uncaught ObjC exception without one, so every build from a clean clone crashed at launch in both configurations. A dormant cloud rung is a correct build — routing stays on device, `DataBoundary` stops claiming anything is transmitted — so it boots and says so in the diagnostics card.
- **The privacy policy must be reachable from INSIDE the app** (guideline 5.1.1(i), because the app collects data). `Models/SupportLinks.swift` holds it; while it is nil the app renders no link at all — a 404 under "Privacy policy" is the first thing a reviewer taps — and the DEBUG diagnostics line reads `privacy policy blocks submission` until an owner sets it.

## Rules — capture (Ramble; `docs/capture.md`)

- **Always-confirm.** Engines emit `TaskIntent`s with raw `dateExpression`/`personReference`; the deterministic `IntentResolver` makes drafts (no lifecycle position) and **backfills every empty field** (importance, effort, owner, kind, due date). Nothing is gated on confidence at capture; the Confirm card is the ONE human-in-the-loop boundary; every edit there is a `Correction`. The single confidence-tiered exception is destructive inference — the duplicate merge (0.85 accept / 0.5 undecided), extended to existing pairs by `DuplicateSweep` (kill-don't-delete, reversible, judged by `-DuplicateSweepEval`, never a judgment call as loser). **The sweep's prefilter is the lexical floor alone; the embedding ranks, it never gates (2026-09-17, on GA device numbers).** History: the 0.82 `embeddingFloor` was calibrated on synthetic unit vectors (≈ cos 0.985) and on 2026-09-12 dropped 10/10 real duplicates, while the beta judge returned one false merge at 1.00 on the prerequisite near-miss ("passport photos") — the reason the floor was not loosened then. On GA the judge scored that pair 0.50 and every duplicate 0.90–1.00 (FALSE MERGE 0/20), and the per-pair printout showed the embedding cannot separate duplicates (sim 0.00–0.18) from near-misses (0.03–0.57) at any floor. With the lexical gate alone the sweep merged 5/10 real duplicates in PRODUCTION with FALSE MERGE 0 (was 0/10); a pair missing a vector still gates on its words. `-DuplicateSweepEval` still prints real `sim`/`lex` per pair; argue any floor from those, never from the synthetic table. **2026-09-17, iOS 27 GA on the phone:** the GA judge scored that prerequisite pair 0.50 and every duplicate 0.90–1.00 (FALSE MERGE 0/20, gap 0.40) — the blocker is lifted on this corpus; and the printout shows WHY the floor admits nothing: in the store's `1 − √(2 − 2cos)` unit real duplicates read sim 0.00–0.18 while near-misses read 0.03–0.57, so the embedding floor cannot separate them at any setting and only the judge can. Moving or replacing the prefilter is an owner call over those numbers, not yet made. Inferred due dates come from a short explicit table (`inferredDueDate`), are suppressed on any blocker phrase, carry a `dueReason`, and never feed importance. A bare clock time means TODAY (`clockTimePattern`, one shared regex; a day word absorbs the clock beside it). A pronoun is not a blocker (`namesSomething`); `isBlocked` is derived from the phrase; **a short wait that OPENS on a pronoun points at the previous draft** (`IntentResolver.resolvingAnaphoricWaits`, 2026-09-17 — "book flights after it comes through" now waits on "Renew my passport…" and commits as a real edge to the sibling, not an external wait called "it comes through"). A capture made only of filler words is nothing (`Segmentation.isBareFiller`, whole line since 2026-09-18 — "hmm ok so" had become a card); categories score by keyword HITS, table order breaks ties, and the kitchen is `Home`. **A comma part carrying its own DEADLINE is an outcome, unless it opens on a pronoun** (`Segmentation.isItemLike`, 2026-09-20): `splitCommaList` vetoes the whole split unless EVERY part is item-like (a verb, or ≤4 words), and one noun-initial part took two unambiguous ones down with it — "renew my passport, book flights after it comes through, and daycare forms are due friday" came back as ONE task titled "Renew my passport, book flights" with the other two outcomes inside a wait chip. Found by eye, on a store screenshot. The pronoun guard is what keeps the third arm honest: "call mom, she's back from the trip on friday" carries a day too and is one task with context. **Measured before it shipped** — against the 2026-09-20 baseline (segmentation 51/52 golden · 23/26 real · false-keep 0 · adversarial false-keep 2 · coverage 96%) the hard case now passes and every other number is unchanged; the corpus case's own labels were wrong on the first run and the eval said so. Any further loosening needs the same evidence: false-keep is the critical error and `email the landlord about the boiler and the leak` sits one heuristic away. **Two clauses that each carry their own day are two outcomes** (`Segmentation.datedOnBothSides`, 2026-09-17): the bare " and " splits "dentist on thursday and the vet on friday" even though the right side has no verb, unless the right side OPENS with a weekday (a day-list, one outcome the resolver fans out) or says nothing but its day; measured on GA these were 2 of the 3 utterances still escalating, the on-device boundary pass answered "one part" for both, and the deterministic read resolves them in 2 ms — correct-local-resolution 89% → 92%.
- **Voice-first: the sheet opens INTO listening** (`ComposerView.RamblePhase`: `.listening → .understanding → .confirm`; `.capture` is the typed escape hatch). The orb reflects reception, never interpretation — no live transcript (it mirrors invisibly into `text`). Silence auto-submits after a fixed 5s that arms only on transcript deltas; orb tap finishes now; an empty finish settles to the canvas. Any non-user drop of speech settles to `.capture` with the words; backgrounding never submits. Every keyboard raise is a deliberate decision. **Never show an intermediate AI interpretation as truth** — test-enforced.
- **The microphone is never hot without a surface, and a stop always stops it (2026-09-20).** `SpeechCaptureService.start()` suspends twice — on the permission prompt and on the first-run model DOWNLOAD — and neither honours cancellation, so a `stop()` during warm-up tore down an engine that was not running yet and the suspended call then came back, installed the tap and set `.listening` on a sheet the person had already left: a live mic with no orb and nothing on screen saying so, and "Getting the mic ready…" at two seconds invites exactly that tap. `startToken` is bumped by every `stop()` and re-checked after BOTH awaits; a start that lost gives the microphone straight back. **A region we do not ship is not a language we do not speak:** `resolveLocale(preferred:supported:installed:)` (pure, `SpeechLocaleTests`) falls back exact → installed sibling → any sibling, sorted, because matching the full BCP-47 identifier switched voice off permanently for `en-NG`/`en-PH`/`en-KE` under a sentence that was not even true. **A framework's error text never reaches the person:** `sentence(for:)` answers in the product's words (`NSError` conforms to `LocalizedError`, so the canvas used to print "com.apple.coreaudio.avfaudio error 561145187"), and `isRetryable` separates a failed download from a verdict about the phone, with Try again beside it instead of a Speak button greyed out for the life of the sheet.
- **A REVEALED INTERPRETATION IS FINAL** — enforced structurally in `Interpretation` (`propose` refuses once `.revealed`; DEBUG fingerprint). The user may always edit their own cards. Product-wide: never expose an AI intermediate as user truth.
- **The cloud rung is OFF — the product reads on the device only (2026-10-04, the owner's call: the product is free and cannot carry a per-call bill).** `CloudModel.isEnabled` is a constant `false` at the ONE gate (`isAvailable = isEnabled && provider.isAvailable`), so capture routing, the Advisor's rung choice and both privacy sentences all follow it, and `AppDelegate` never configures Firebase (no App Check handshake, no network behind the seam) — "off because a gitignored plist was absent" would have been reversed by any archive made on a machine that has the file. Baseline with zero cloud calls (`-RambleEval`, 2026-10-04): segmentation 52/53 golden · 23/26 real, every other column 100%, 96% of unstructured captures kept local, false-keep 0. **Not yet measured on-device-only, and the cost of removing the cloud:** a ≥400-character dump (`bigDump` went straight to the cloud) and chatty speech with no task in it (`conversation`: the cloud could answer NOTHING; the local reader makes junk cards). The fallback under design is one task from the whole text with a "Split into N?" offer, never a model arm that segments. `CloudOffTests` pins the gate and the guarded `configure()`. The provider, `CloudBudget`, `CloudHealth`, App Check and the kill switches stay until a removal pass deletes them together with the manifest's raw-words type and the policy's escalation paragraph. While the flag is off the App Check deadline (2026-11-02) and the App Attest capability are moot.

## Two-engine AI

`AI/AIEngine.swift` is the seam; `FoundationModelsEngine` (on-device / cloud by `SessionSource`) and `HeuristicEngine` (deterministic) both emit `[TaskIntent]`; `AppBrain` selects at launch and degrades to the heuristic. **The simulator may run the REAL on-device model** (it follows the host Mac's Apple Intelligence) — read the DEBUG footer, never assume; the sim cannot verify off-device behaviour. **`EmbeddingStore.sentenceEmbedding` is a RETRYING accessor, never a `static let`** (2026-09-12): `NLEmbedding.sentenceEmbedding(for:)` returns nil on the FIRST call in a process and succeeds later — on the phone AND the simulator — and a `static let` froze that nil at `prewarm` for weeks (0 `EmbeddingCache` rows against 70 tasks; retrieval lexical-only; the sweep never judged a pair). A success is cached, a nil is re-asked, `settle()` for callers comparing two retrievals, `EmbeddingStore.statusLine()` is the meter in the diagnostics card. *A `static let` over a platform lookup that can transiently fail is a frozen failure; a graceful degrade with no meter is a feature that can be off for a month.* Reasoning: `docs/capture.md`. Unit tests always see the heuristic (`onDeviceAvailable()` is false under XCTest). Keep both engines consistent through `AutonomyPolicy.tier` + `IntentResolver` (incl. `applyRules`). `TriageContext` carries personalization, roster (`ResolvePersonTool`), candidates (`ContextRetrieval`, cap 12 — the ONLY ids the model may cite) and suppressions; `CaptureSessionPool` prewarms single-use sessions; edge proposals are tiered by destructiveness (`duplicateOf` 0.85/0.5, `childOf` ≥0.5).

**Every argument read sits inside `#if DEBUG`, and `ReleaseSeamTests` proves it by WALKING the app target** for `ProcessInfo.processInfo.arguments` rather than by a list of files someone remembered (2026-09-20 — the list held two files and the walk found six unfenced seams in three others, `-CaptureDiagnostics` among them, which runs a 14-item corpus through `brain.triage` and tees stdout into Documents). **Never gate this with `strings`:** Swift keeps any literal of ≤15 UTF-8 bytes inside the `String` value, so it never reaches the binary — `-SeedSampleData` (15), `-OpenSettings` (13) and `-OpenRoster` (11) are all invisible to it, and the 2026-09-11 leak was caught only because `-ResetAndSeedEvalCorpus` is 23 characters long.

Synthetic taps are blocked on this host — use a seam, never AppleScript. Every eval enforces zero-cloud unless flagged (the provider slot holds `EvalQuotaGuard`, and the `providerCalls` delta is the receipt), prints a DEGRADED banner under 90% served naming the error (`AppBrain.errorLine` — the GA payload, e.g. a throttle's reset date, beside the stable `errorLabel` key), and opens with `Instrument.runStamp` (app · OS version AND build · `sim:`-prefixed device on the simulator · model · config fingerprint · time — the OS build is the on-device model's only version fingerprint, and a simulator number is Mac silicon, never a phone number). **Device runs from the CLI:** `xcrun devicectl device process launch --device <id> --terminate-existing <bundle> -- -Flag -EvalToFile` passes the args (`scripts/device-evals.sh` is the loop); phone unlocked, Auto-Lock Never — a locked screen backgrounds the app and the on-device model answers `rateLimited` until it returns (2026-09-17: the Ramble direct arm wedged at case 36/52 that way).

## Device notes

- **The cloud rung is inert until Firebase is configured** (`AppDelegate` → `FirebaseApp.configure()`; the unit-test host skips it). **App Check's client half is wired; the console half is not — deadline 2026-11-02.** `AppCheckSetup.install()` runs BEFORE `configure()` (after is accepted silently and fails at the first token). App Attest on device with a DeviceCheck fallback; the App Attest entitlement is deliberately ABSENT until the App ID capability is on (adding it first breaks signing). `AppCheckSetup.statusLine()` counts down in the diagnostics card.
- `GoogleService-Info.plist` is gitignored; it sits in the synchronized group and needs no pbxproj entry.
- **Device signing carries the iCloud container since 2026-09-17** (`xcodebuild -destination id=<phone> -allowProvisioningUpdates` from a clean `main` signs with `iCloud.amanze-studios.Project-Ezra` in the entitlements and installs). Before the App ID had the capability it answered *No Accounts* / *profile doesn't support the iCloud Identifier*, and a failed signing step leaves a HALF-SIGNED bundle in the shared DerivedData that every later install trips on (`0xe8008001 integrity could not be verified` — this masqueraded as a locked phone for an hour on 2026-09-12); `scripts/device-evals.sh` builds into an isolated `-derivedDataPath` for that reason.
- **The phone must not auto-lock for the length of a device eval** (Settings ▸ Display & Brightness ▸ Auto-Lock ▸ Never): a suspended run keeps its process and its report freezes mid-file. Both device harnesses print a heartbeat per judgment so a stalled count can be told from a slow one.

## Workflow

- **Two ways onto `main`, by who is committing.** The owner's local sessions commit directly to `main` and push. Cloud/background Claude sessions work on a `claude/<name>` branch and open a PR; the owner merges it on GitHub (no CI, so the PR is the review). **Every local session starts with `git fetch && git status`** — a merged PR lands as a merge commit on `origin/main`, so local `main` diverges silently (2026-09-17: 21 unpushed local commits over 2 remote ones). Reconcile with `git rebase origin/main`, never a merge commit from the local side. A merged `claude/*` branch is deleted; an OPEN PR's branch is left alone — it may be a docs-only audit awaiting the owner's read.
- **`docs/cohort0-checklist.md` is the audit's ground truth — update it in the same change that changes a flow.**
