Rules for working in this repository. **This file keeps the rules; `docs/decisions.md` keeps the full text every rule was compressed from (verbatim, same headings — grep a rule's bold lead there for its history), and the topical docs keep the why.** A rule that changes here changes there too.

## What this is

**Project Ezra** ("Managing Chaos, Effortlessly") — an AI-managed household task system for iOS. SwiftUI + Core Data, single app target. **The product spec is not in this repo:** *Ezra Product Shape v8* (https://claude.ai/code/artifact/aa4e89a0-a1ff-4ed2-b0f8-c6e227ed7014) is the source of truth for what the product is and what the MVP cuts; where any file here disagrees with it, the artifact wins. **Kinly** is the launch positioning layered over v8 (`docs/kinly-launch-plan.md`) — not a rename (the name stays Ezra until the App Store/trademark check) and not a new spec.

The repo keeps architecture and craft: `docs/README.md` (the map) · `docs/task-model.md` (the four axes) · `docs/primitives.md` (the durable core + the bloat-watch test) · `docs/capture.md` · `docs/advisor.md` · `docs/surfaces.md` · `docs/platform-notes.md` · `docs/decisions.md` · `docs/cohort0-checklist.md` · `prev-docs/design-system-managing-chaos.md` · `prev-docs/product-guardrails.md` · `prev-docs/household-architecture.md`.

## Posture — research preview, on purpose

Single-developer R&D build, deliberately on the newest software (iOS 27 GA from 2026-09-17 — Xcode 27.0, macOS 27.0, Foundation Models year-two APIs, Firebase's public-preview `GeminiLanguageModel`; it was betas and a branch pin before that). Do not gate a capability on evidence that does not exist yet — turn it on, then measure (evals *tune* what runs, never grant permission). No "wait for GA" caveats. Do not soften a capability without being asked. Two things this never relaxes: **safe defaults for data** (the deterministic tail always exists, `validated(against:)` rejects untrusted model output, corrections never leave the device) and **the guardrails** (`prev-docs/product-guardrails.md`).

```bash
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=27.0' \

```

Prefer `/run-sim` for install + launch + screenshot. A clean build is sufficient to call a change done. Tests live in `Project-EzraTests/` (`@testable import Project_Ezra`) and cover the pure AI/ranking logic — add cases there when you touch it. **Known flake:** every case green but the run ends `TEST FAILED` via `Restarting after unexpected exit` with zero Core Data exceptions — the Xcode 27 beta sim's accessibility-bundle conflict; re-run. A run with `✘` cases or an `NSInvalidArgumentException` is real.

## Project layout & Xcode gotcha

- `Project-Ezra/` is a **PBXFileSystemSynchronizedRootGroup**: create or delete `.swift` files and they compile; **never hand-edit `project.pbxproj` for files** (build settings and SPM packages only — the Firebase and Statsig entries are hand-authored and the pattern to copy).
- Feature-organised: `Design/` · `Models/` (Core Data models, `PersistenceStack`, pure ranking) · `AI/` (engines, seams, evals) · `Features/<Screen>/` · `Features/Components/` · `Intents/`. The task model is `Models/TaskItem.swift`; models are built with the `in:` context inits.
- Three seams to know before reinventing one: **`AI/SerialGate.swift`** (one-at-a-time execution; the stored task wraps the WORK, not the wait; `peakActive` for tests), **`AI/CaptureProvenance.swift`** (per-capture receipt as a JSON file sidecar via `Models/Sidecar.swift` — *a diagnostic must never be able to cost the user their data*; every diagnostic follows), **`AI/DeterministicReading.swift`** (rung 0's Advisor reading).
- **Swift-format** runs on every edited `.swift` via a PostToolUse hook (`.swift-format`: 4-space, 110 col). Don't hand-align.

## Rules — task model (`docs/task-model.md`)

- **Four axes, never fused.** (1) Lifecycle `TaskStatus` (`.todo → .doing → .done | .canceled`), user-owned; a `TaskItem` exists at Confirm and never before (pre-Confirm state is a parked `Capture`; `AppBrain.commit` IS the confirm; `status.isLive`). (2) Type `WorkIntent` (action/planning) — INTERNAL, system-owned, never a chip, never user-edited, never nil at creation (`IntentResolver.inferredWorkIntent` backfills, and never reads `isJudgmentCall`/`needsDecision`); retired cases decode additively. (3) Attention flags — `needsDecision` stored; Blocked/Blocking/Overdue/Stale derived on read. (4) Signals — `isUrgent` human-declared feeding a persisted 0–100 score (`AttentionEngine` → `AttentionMetadata`) that only breaks ties within bands; never a badge; reads slow inputs only. Adding a blocker must not move status; confidence must not auto-resolve a judgment call.
- **Judgment calls are a permanent carve-out:** always `.ask` tier (`AutonomyPolicy.tier`), `needsDecision` from birth, only `resolveDecision()` clears it; `BrainSweeps` never touches one; `autonomy` is derived, not stored.
- **Every status change goes through `TaskItem.status`'s setter** (`transition(to:now:)` records the `StateVisit` timeline and bumps `updatedAt`). Never write `statusRaw`; never expose `$task.status`; **every mutation helper bumps `updatedAt`**.
- **Blocked is derived, never written** (`activeBlockers(among:)`); no `block()`. Edges live in one versioned `relationshipsData` blob (`Models/Relationship.swift`, kinds `.blocks/.parent/.related`, each with an `Origin`); `blockers`/`parentTaskID` are read-only views; **every write goes through `TaskMutations`**. A rejected suggestion is a `RelationshipSuppression`, never a dismissed edge. The umbrella-before-steps fact is DERIVED (`openSteps`/`stepProgress`), never a stored wait; `splitInto` writes one edge per step ON the step; `TaskChainGrouping.prerequisites(of:within:)` is the ONLY place the two graphs meet. Display order of steps IS `sortIndex`; `children(among:)` is the one ordered derivation.
- **The row's leading marker is one slot with two residents** (`SignalMarker`: Needs Decision wins over Urgent; never the type). **The primary CTA is one slot or none** (`RecommendedAction`: resolved → Reopen · unowned → That's mine · someone else's → **nil, by design** · blocked → Unblock · `.todo` → Start · `.doing` → Mark done). The verb never voices the type — one view-layer carve-out: on a `.deciding` page `.start` reads "Decide". Start relabels in place; only `.resolve` dismisses. **List gestures, one meaning each:** tap opens detail; leading swipe = `performRecommendedAction` (absent when nil); trailing swipe cancels (absent on resolved); long-press = menu. The glyph's status menu is retired. Never a second button under the CTA.
- **Stack precedence** (`Models/TaskRanking.swift`): Needs Decision top → Blocked sinks → effective attention desc → Blocking → Overdue, as lexicographic keys (strict weak ordering, property-tested). The ONE additive layer is `attention.score + currentRelevance` (live, clamped ±25): staleness pulls down (from `lastHumanTouchAt`, consecutive and cleared by `touchHuman`); unblock/dependent/due/`startedBoost` (current open `.doing` visit only) pull up. **`.doing` may touch this layer and no other.** Precomputed once per snapshot into `RankKey`, never inside the comparator. The deferral pull-down is DELETED, not repointed (an abandoned start is the opposite of a soft "not today").
- **Ownership: every task is born owned.** `OwnerProposer` is total and deterministic (spoken → adjacency via `childOf`/`duplicateOf`, never blockers → affinity → the capturer); "unowned" is exactly `ownerID == nil` and only a human hand-back produces it; load adjusts, never selects. `.defaultSelf` carries no reason and no ✦. `ownerOrigin` (`.human`/`.inferred`) is stored because the affinity denominator counts human ownership only. `creatorID` is authorship.
- **Confirm is the single publish boundary** (`AppBrain.publishAssignments`); assignment side effects bind to it, never to the owner field. Target behaviour is *notified*; the interim is a silent publish.
- **Undo-completeness:** a `ChangeLogUndo` arm restores every field its action wrote (e.g. `"assigned"` encodes `"<uuid>|<origin>"`). `ChangeLogEntry` backs Undo and the trail; `initiatedBy` separates AI from human; `Metrics.acceptanceRate` counts AI entries only, excluding `"planned"`.

## Rules — sync, persistence, schema

- **`HouseholdSync.isLive` is `true` (2026-09-12)**, flipped as ONE act with `PersistenceStack.cloudKitContainerID` (`iCloud.amanze-studios.Project-Ezra`), the entitlement and `CKSharingSupported` (`SyncGateTests.gateIsOpenAsOneAct`). The `Household` is the root of a `CKShare` in the owner's private database; model v4 gave `TaskItem` and `ChangeLogEntry` a `household` edge so the plan and trail ride the share; `Correction`, `Capture`, `EmbeddingCache`, `SuppressionRecord`, `UserProfile` have no edge and never travel. Two stores in one `NSPersistentCloudKitContainer` (private, then shared); **`HouseholdStoreAffinity` decides the store once, at save, for every creation site** — never assign a store at a creation site. `Household.existing(in:)` prefers the largest roster. The unit-test host never constructs the CloudKit container (`usesCloudKit`).
- **The invite is one link** (`Features/Household/HouseholdSharing.swift`): the share URL with public read-write permission plus an `Invitation` naming the member; `SceneDelegate` receives the tap; identity links without asking only when exactly one invitation is pending, otherwise `IdentityLinkSheet` asks — never guessed from a name. Every stage is a `TelemetryInviteStage`. The simulator proves none of the CloudKit half; the two-phone sitting is in `TODO.md`.
- **`schemaGeneration` is FROZEN at 10** (`Project_EzraApp.frozenSchemaGeneration`, `SchemaFreezeTests` reads the compiled `.mom`s). Every model change is a NEW `.xcdatamodel` version that is a superset of the last — nothing removed, no type changed, optional→required forbidden, every attribute optional or defaulted, every relationship inverse-paired. A meaning change is a new field beside the old. **Never edit the current model version in place** (Editor ▸ Add Model Version; hand-authoring the directory works); the DEBUG digest tripwire tells the safe act from the mistake by membership in `bundledModelVersionDigests`. Current: `ProjectEzra 4.xcdatamodel`.
- **Every reset takes a safety copy first and is reported**: `PersistenceStack.destroyStore(reason:)` backs up both stores' sqlite + `-wal` + `-shm` (last 5), writes a `StoreResetRecord` Settings leads with, no in-app restore. `DataExport` is the readable JSON snapshot. Never touch `PersistenceStack.scratch`'s objects en masse.
- **Every `saveChanges()` result is checked** — a dropped save must leave a trace.

## Rules — capture (Ramble; `docs/capture.md`)

- **Always-confirm.** Engines emit `TaskIntent`s with raw `dateExpression`/`personReference`; the deterministic `IntentResolver` makes drafts (no lifecycle position) and **backfills every empty field** (importance, effort, owner, kind, due date). Nothing is gated on confidence at capture; the Confirm card is the ONE human-in-the-loop boundary; every edit there is a `Correction`. The single confidence-tiered exception is destructive inference — the duplicate merge (0.85 accept / 0.5 undecided), extended to existing pairs by `DuplicateSweep` (kill-don't-delete, reversible, judged by `-DuplicateSweepEval`, never a judgment call as loser). **The sweep's prefilter is the lexical floor alone; the embedding ranks, it never gates (2026-09-17, on GA device numbers).** History: the 0.82 `embeddingFloor` was calibrated on synthetic unit vectors (≈ cos 0.985) and on 2026-09-12 dropped 10/10 real duplicates, while the beta judge returned one false merge at 1.00 on the prerequisite near-miss ("passport photos") — the reason the floor was not loosened then. On GA the judge scored that pair 0.50 and every duplicate 0.90–1.00 (FALSE MERGE 0/20), and the per-pair printout showed the embedding cannot separate duplicates (sim 0.00–0.18) from near-misses (0.03–0.57) at any floor. With the lexical gate alone the sweep merged 5/10 real duplicates in PRODUCTION with FALSE MERGE 0 (was 0/10); a pair missing a vector still gates on its words. `-DuplicateSweepEval` still prints real `sim`/`lex` per pair; argue any floor from those, never from the synthetic table. **2026-09-17, iOS 27 GA on the phone:** the GA judge scored that prerequisite pair 0.50 and every duplicate 0.90–1.00 (FALSE MERGE 0/20, gap 0.40) — the blocker is lifted on this corpus; and the printout shows WHY the floor admits nothing: in the store's `1 − √(2 − 2cos)` unit real duplicates read sim 0.00–0.18 while near-misses read 0.03–0.57, so the embedding floor cannot separate them at any setting and only the judge can. Moving or replacing the prefilter is an owner call over those numbers, not yet made. Inferred due dates come from a short explicit table (`inferredDueDate`), are suppressed on any blocker phrase, carry a `dueReason`, and never feed importance. A bare clock time means TODAY (`clockTimePattern`, one shared regex; a day word absorbs the clock beside it). A pronoun is not a blocker (`namesSomething`); `isBlocked` is derived from the phrase; **a short wait that OPENS on a pronoun points at the previous draft** (`IntentResolver.resolvingAnaphoricWaits`, 2026-09-17 — "book flights after it comes through" now waits on "Renew my passport…" and commits as a real edge to the sibling, not an external wait called "it comes through"). A capture that is one filler word is nothing (`Segmentation.isBareFiller`); categories score by keyword HITS, table order breaks ties, and the kitchen is `Home`. **Two clauses that each carry their own day are two outcomes** (`Segmentation.datedOnBothSides`, 2026-09-17): the bare " and " splits "dentist on thursday and the vet on friday" even though the right side has no verb, unless the right side OPENS with a weekday (a day-list, one outcome the resolver fans out) or says nothing but its day; measured on GA these were 2 of the 3 utterances still escalating, the on-device boundary pass answered "one part" for both, and the deterministic read resolves them in 2 ms — correct-local-resolution 89% → 92%.
- **Voice-first: the sheet opens INTO listening** (`ComposerView.RamblePhase`: `.listening → .understanding → .confirm`; `.capture` is the typed escape hatch). The orb reflects reception, never interpretation — no live transcript (it mirrors invisibly into `text`). Silence auto-submits after a fixed 5s that arms only on transcript deltas; orb tap finishes now; an empty finish settles to the canvas. Any non-user drop of speech settles to `.capture` with the words; backgrounding never submits. Every keyboard raise is a deliberate decision. **Never show an intermediate AI interpretation as truth** — test-enforced.
- **A REVEALED INTERPRETATION IS FINAL** — enforced structurally in `Interpretation` (`propose` refuses once `.revealed`; DEBUG fingerprint). The user may always edit their own cards. Product-wide: never expose an AI intermediate as user truth.
- **Routing is device-first, escalate on evidence** (`AI/CaptureRoute.swift`, `AI/CaptureEscalation.swift`): `.local` (deterministic, p90 2ms) is the default; the capture transmits only with a named reason — `emptyRead` · `bigDump` (≥400 chars/≥6 items, straight to Gemini) · `underSegmented` (unaccounted boundaries ≥2; verifier-only signals may count but never cut) · `unresolvedDetail` · `lowCoverage` · `conversation` (spoken only; the authority may return NOTHING). The verifier asks no model and can only escalate. **`AppBrain.triage` has NO default route** — every caller states it; composer-free callers use `CaptureFlow.route(for:posture:)`. Structure the user typed never touches the network. There is always a free tail (`captureNeverBlocks`). The FM on-device model is OUT of the capture chain (measurable as `-RambleEval`'s `on-device(direct)` arm and `-FMDiagnostics`); it is a CANDIDATE for Ramble primitives after the GA evaluation, decided by a human over `-FMPrimitives`.
- **The boundary pass** (`AI/OnDeviceSegmenter.swift`) is built and **OFF** (`isRoutingEnabled`): the model names verbatim anchors, the app cuts, `CaptureEscalation.reason` is re-asked and final; nothing invented, nothing lost, grounding total (one missing anchor rejects the artifact); reachable only on `underSegmented` and on the on-device posture (`CaptureFlow.Arm.boundaryPass`, `boundaryPassAvailable` a REQUIRED parameter); **a cut is a gain only above the local read's count** (`isGain`, 2026-09-17 — the GA model cut a 3-outcome utterance into 2 on one run in four and the validator accepted the merge; now `.noGain`, and `-FMPrimitives` scores a no-gain over an already-right local read as `stand-aside`, not as a missing artifact). `-FMPrimitives` reports REACHABLE · POSTURE · POTENTIAL cohorts, gates fixed for the campaign, and `Instrument.runStamp` on every report; it scores the CUT count against the intent count (never the resolver's draft count, which fans a day-list — that mis-scoring read the GA model's correct 8-part cut as a false accept on 2026-09-17) and prints the model's anchors on a FALSE-ACCEPT row. **GA verdict (2026-09-17, 24A437):** FALSE ACCEPT 0/0, precision 100%, p50 1.31 s / p95 2.46 s in envelope; HOLD only on REACHABLE recall (1/3 exact — two "one part" refusals).
- **The cloud arm is `FoundationModelsEngine` with a different `SessionSource`, not a second engine** — same instructions, schema, verbatim-quote grounding and resolver on both arms. `triage` records the rung ACTUALLY taken. Candidates ride the chain (retrieval concurrent with generation, bounded by `candidateWaitSeconds` 0.25s) — **a feature whose enabling input is an unset default parameter fails silently and tests green; assert threaded data at the point of use.** Capture-time model reasoning streams internally; the user receives ONE final interpretation. Provisional deterministic cards render first; `DraftMerge` Pass C survives for the re-submit path only.
- **Capture is the conservative stage**: understand what was said; never invent a task's existence. `ExtractedTask.sourceQuote` must be found in the raw capture (`AppBrain.grounded`) or the task is dropped, never substituted. **One task per distinct intended OUTCOME** — quantity/cadence never multiplies, named occasions do; the model hands the phrase over, `IntentResolver.expand` fans out (all-or-nothing, `maxInstances` 7). **Structure is decided ONCE at submit** (`Segmentation.structure(of:)`: `.explicit` or `.unstructured`). The deterministic title is a task, not a transcript (`cleanTitle`, meta-narration stripped, a cut-off "at" becomes the "When?" ask).
- **Budgets and hedges:** deadlines derive from `WaitContext` via `ModelDeadline.seconds(for:)`; capture's is sized by WHY the words left (`captureSeconds(for:)`: 30s for dumps/empty reads, 10s standby when a plausible read is in hand); a deadline hit on a long ramble is `.salvaged`, not a failure — chunk, never raise. The hedge is retired (`hedged(hedge: nil)`); a cancelled capture is not a timeout. **Capture does not consult `CloudBudget`.** The on-device confidence GATE was built, measured (2303ms, 95–100% escalation) and deleted — do not rebuild without new evidence. **Bracket every new metric before pointing it at a model** (the instruments lie more often than the code).
- **Privacy is per-workload and stated in plain words** (`Models/DataBoundary.swift`, no vendor names, test-pinned): Ramble's raw capture is the ONE sanctioned raw-text transmission (`transmitsRawCapture`), audio never leaves, Advisor sends structured snapshots, corrections/history never leave; sentences for sync and telemetry appear only while each is true. **Privacy is a POSTURE on the one door** (`Models/CapturePosture.swift`: `Read anywhere`/`On device`; on device outranks the router; a single thought runs `PrivateCaptureEngine`; grep-pinned against the cloud seam). **The composer holds ONE `PrivateCaptureEngine` for the sheet's life** (2026-09-17): prewarm on appear, `transcriptChanged` on every delta, `silenceArmed` when the window arms for a single thought, `finish` at submit, `cancel` on disappear — a fresh engine at submit reached none of that and every private capture paid the cold read; measured on the phone the wait after the window fell from p50 1308 ms to 5 ms (19/19 speculative), the receipt's `armWon` says which path served. **Ramble economics** (five rules, `docs/capture.md`): no visible quota; models produce artifacts, deterministic validators decide acceptance (false accept is the critical error); every cloud call metered from `Response.usage`; every report run-stamped, quality/latency gates and cost the optimizer; Remote Config / kill switches may turn a pillar's cloud arm off, never a floor.
- **The reveal shows the consequence, not the classifier** (`isJudgmentCall` only — never `draft.needsDecision`; `.planning` reads "Needs a plan"; uncertainty is not a visual state; the TARGETED ASK is `TaskDraft.unresolved` → "When?" chip, never on an undated task). The orb (`RambleOrb`) is a two-hue `MeshGradient` sphere, never a spinner — rate, not shape, decides it; audio controls presence never speed; both mode branches live in ONE `case .listening, .understanding:`; minimum dwell `orbMinimumDwellSeconds`; judge on VIDEO. **Create ends the loop immediately**; the count is unstated; only a merge speaks after (`UndoNotice`). The 2026-09-04 surface pass and the three composer layout traps are pinned in `CaptureSurfaceTests` and `docs/capture.md`.
- **Eval floors live in the app target** (`AI/RambleEvalSet.swift`, `RambleEval.Floors`): CI and `-RambleEval` read the same numbers; the real-utterance corpus (`realSet`, `Floors.real`) is quarantined; every model arm proves it ANSWERED (served <90% = DEGRADED, naming the error); the cloud arm is opt-in (`-WithCloud`, quota-guard provider otherwise). Re-calibrate floors only downward from observed numbers.

## Rules — Advisor (`docs/advisor.md`)

- **A judgment layer, not a feature catalog**: one ambient surface answering *what would make this task easier right now* — observation · guidance · next move. The model judges the shape of help (`AdvisorMove`; `start` is not a move); the deterministic system stays authoritative through sensors (`StallDetector`/`BreakdownEligibility`/`DecisionShape` → FACT lines), the gate (`TaskCapabilities.advisorWorthy`, a cost heuristic) and the off-device fallback.
- **Rung 0 always has an answer** (`DeterministicReading`, shape-aware, additive, never restating the spine; the dependents arm yields to `.waiting`); `.timedOut`/`.failed` degrade to it; a floor reading is not an `offer`. External waits reach the facts. **Silence is a first-class judgment** (`.quiet(.gate)`/`.quiet(.model)`); `.quiet(.model)` renders as one muted bar line ("Looked just now — nothing to add."). The loop closes on `task.updatedAt` and `openedBlocker`. `TaskAdvisorGoldenTests` (injected judge) is the acceptance gate.
- **Every "ask Ezra" surface is ONE primitive — `AI/Inquiry.swift`**: scope → facts → floor or model → validate → at most one move. `TaskInquiryScope` and `HouseholdInquiryScope` are conformances (on-device only, grep-pinned; never act; revealed whole; `ThinkingLine` in the pending slot). The Advisor reading is a zero-turn inquiry (`mode: .reading`); `InquiryService` owns every on-device session plus one warm spare. Both chats open keyboard-DOWN when there is a reading to read. Cited rows carry the list's two swipes on both chats (`ChatCitationParityTests`).
- **The facts fingerprint is the calm invariant**: same task + same meaningful context → same reading; `AdvisorRevealGate` refuses a second reveal per fingerprint; dismiss binds to it. **Model output is untrusted transport; `ValidatedReading` is the contract** (drops/degrades, never substitutes; options 2–4, steps 2–5, `openBlocker` needs a real blocker). Rung 1 is durable (`AdvisorReadingCache`, sidecar). Dismissals are `HumanVerdict`s (sidecar) and teach (`Learned`, threshold 2, cap 8 — the ONE learner over `HumanVerdicts.collect`).
- **Presentation:** ONE home — a single line in the pinned bar under the CTA (`TaskDetailView.advisorLine`) that opens the task chat, where the reading is the opener; moves run through `AdvisorActions`. The flagged decision's reason line and its button stay on the PAGE; that button reads **"I've decided"** (first person; the pinned CTA is imperative, a control reporting a reached state speaks as the human; alert confirm "Record"). The Advisor never wears `accentGradient`; the reading is containerless and label-less; a failed generation renders nothing; "Why this?" shows evidence, never reasoning (`userVisibleEvidence`, `workIntent` excluded). The Start tap earns a kickoff line (containers from `nextOpenStep`, deciding tasks none, else `KickoffService`).
- **The router asks for a REASONING BUDGET** (`ReasoningBudget`: none/shallow/deep; `depthReason` `.decision` · `.multiStep` (blockers + open steps ≥ 2) · `.repeatedlyAbandoned` (`abandonedStarts >= 2`, in the FINGERPRINT)). Every depth reason must be reachable (`ReasoningBudgetTests.everyDepthReasonIsReachable`). `StallDetector` and the `.dying` headline read `recentAbandonedStarts` (windowed, silent while `.doing`); `StallDiagnosis.headline` takes both counts as REQUIRED parameters. **`InertSignalTests`** guards fields the app can no longer write (`deferralCount`, `carriedOverCount`) — prose may name a dead field, code may not read one; a fixture describing an unreachable state is worse than none.
- **Routing is DISCOVERED** (`-AdvisorBenchmark`: the strongest rung sets the ceiling, cheaper rungs earn cases by move equality, modal across `-AdvisorRepeats`, printing `OVER-CLAIMED`/`UNDER-CLAIMED`); the routing percentage is an output. **Depth is not length.** Latency is a budget per rung (`advisorSeconds(rung:presenceTime:)`: on-device 20s, precomputed deep 60s, presence-time deep 25s salvaging DOWN a rung). Deep judgments run off the open moment (`precompute`, `.shallow` skipped, half the daily cap) — **generated is not offered; SEEN is offered** (`Entry.pendingOffer`). The quality signal is progression LIFT against a judged-silence control (`AdvisorMetrics.progression(among:)`), never AI activity.

## Two-engine AI

`AI/AIEngine.swift` is the seam; `FoundationModelsEngine` (on-device / cloud by `SessionSource`) and `HeuristicEngine` (deterministic) both emit `[TaskIntent]`; `AppBrain` selects at launch and degrades to the heuristic. **The simulator may run the REAL on-device model** (it follows the host Mac's Apple Intelligence) — read the DEBUG footer, never assume; the sim cannot verify off-device behaviour. **`EmbeddingStore.sentenceEmbedding` is a RETRYING accessor, never a `static let`** (2026-09-12): `NLEmbedding.sentenceEmbedding(for:)` returns nil on the FIRST call in a process and succeeds later — on the phone AND the simulator — and a `static let` froze that nil at `prewarm` for weeks (0 `EmbeddingCache` rows against 70 tasks; retrieval lexical-only; the sweep never judged a pair). A success is cached, a nil is re-asked, `settle()` for callers comparing two retrievals, `EmbeddingStore.statusLine()` is the meter in the diagnostics card. *A `static let` over a platform lookup that can transiently fail is a frozen failure; a graceful degrade with no meter is a feature that can be off for a month.* Reasoning: `docs/capture.md`. Unit tests always see the heuristic (`onDeviceAvailable()` is false under XCTest). Keep both engines consistent through `AutonomyPolicy.tier` + `IntentResolver` (incl. `applyRules`). `TriageContext` carries personalization, roster (`ResolvePersonTool`), candidates (`ContextRetrieval`, cap 12 — the ONLY ids the model may cite) and suppressions; `CaptureSessionPool` prewarms single-use sessions; edge proposals are tiered by destructiveness (`duplicateOf` 0.85/0.5, `childOf` ≥0.5).

- **Device signing carries the iCloud container since 2026-09-17** (`xcodebuild -destination id=<phone> -allowProvisioningUpdates` from a clean `main` signs with `iCloud.amanze-studios.Project-Ezra` in the entitlements and installs). ## Workflow

- **Two ways onto `main`, by who is committing.** The owner's local sessions commit directly to `main` and push. Cloud/background Claude sessions work on a `claude/<name>` branch and open a PR; the owner merges it on GitHub (no CI, so the PR is the review). **Every local session starts with `git fetch && git status`** — a merged PR lands as a merge commit on `origin/main`, so local `main` diverges silently (2026-09-17: 21 unpushed local commits over 2 remote ones). Reconcile with `git rebase origin/main`, never a merge commit from the local side. A merged `claude/*` branch is deleted; an OPEN PR's branch is left alone — it may be a docs-only audit awaiting the owner's read.
