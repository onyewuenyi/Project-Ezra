## Cross-cutting

**The token file documents features that no longer exist, and code confirms it.** `Design/Motion.swift` carries an entire "Today sequence (spec §4.3)" block (`beatAdvance`, `heroSettle`, `capsuleExpand`, `planLanding`, `briefingReveal`, `countUp`, plus the `beatRecede` transition, `Motion.swift:44-62,251-258`) written for the Brief's Recap → Docket → Plan sequence. `CLAUDE.md` says the Brief was cut 2026-09-02 and the Brief's code removal is a "separate, named follow-up, not done yet" — but `Features/Brief/` is already gone from the tree. A repo-wide grep for each token's usage shows `capsuleExpand`, `planLanding`, `briefingReveal`, and `countUp` are referenced nowhere outside their own definitions and doc comments; `beatRecede` likewise has no call site. Only `heroSettle` (repurposed for the capture reveal) and `beatAdvance` (repurposed for the detail pager's page turn) survived by being reused for something else. A shared design-token file — the one place this repo says is "the single source of truth" — is carrying five dead constants with paragraph-length comments describing a "Recap numeral" and "day's centerpiece landing" that a reader will not find anywhere in the running app. Delete the five, or file the removal alongside the rest of the Brief cleanup.

**Whole-row tap targets are built on `.onTapGesture`, not `Button`, in three places.** `Features/Tasks/TaskRow.swift:155`, `Features/Components/TaskCardView.swift:177-179`, and `Features/Activity/ActivityView.swift:174` each wrap an entire list row in `.contentShape(Rectangle()).onTapGesture { ... }` to open a detail sheet, rather than a `Button`. This is the exact anti-pattern this review is instructed to flag: it fails standard affordance (no default pressed-state feedback for the primary navigation gesture — `TaskRow` only shows a press highlight on a *held* long-press via a separate `onLongPressGesture` sensor, never on a quick tap-and-release) and it is a real, cross-cutting instance rather than a one-off. It also contradicts the project's own stated rule: `Design/Motion.swift`'s `PressableStyle` doc says plainly, "Buttons must confirm the interface heard the touch — the biggest cross-cutting gap this closes" — yet the single most common gesture in the app (open a task) is exempt from it. All three call sites do compensate with `.accessibilityAddTraits(.isButton)` and a real `accessibilityLabel`, so VoiceOver is not broken — the gap is felt as "no visual acknowledgment of a tap" for sighted users, not as an assistive-tech failure.

**Sub-caption glyph badges are frozen against Dynamic Type, in the exact shape the design system warns against.** `Features/Components/ActivityRow.swift:150` (`.font(.system(size: 8, weight: .bold))` inside a fixed 14×14pt badge) and `Features/Detail/DetailActivityTimeline.swift:138` (`.font(.system(size: 7, weight: .bold))` inside a fixed 12×12pt badge) both hardcode a literal point size for the small action-glyph badge overlaid on an avatar. `Design/Typography.swift:124-127` states the rule this violates almost verbatim: "Reach for the `Font.glyph*` tokens above rather than `.system(size: IconSize.x)` — the raw values are fixed sizes and don't scale," and names `IconSize.micro`/`.nano` (11pt/9pt) as the tier for exactly this ("chip icons... the sub-`caption` chip glyphs"). Neither call site uses `IconSize` at all, let alone a scaled `Font.glyph*` token — at accessibility text sizes, the badge and its glyph stay pinned at 7-8pt while every text label around it grows, so the action icon becomes proportionally illegible exactly where legibility matters most. The two sites are also structurally identical (`ActorAvatar` + `Image(systemName:)` badge + circular tint + white-bordered offset) — a duplicated composition that belongs in one shared "avatar with action badge" component instead of being hand-rolled twice with drifting values (14pt/8pt vs. 12pt/7pt for the same idea).

**The app forces dark mode, leaving a fully-built light `Palette` provably unreachable.** `Project_EzraApp.swift:162` sets `.preferredColorScheme(.dark)` on the whole app (`OnboardingView.swift:68` redundantly repeats it). This is a stated, deliberate choice ("dark-first reads premium; matches the 'quiet' thesis" — the inline comment), not an oversight, and dark-only apps are an accepted pattern. But `Design/Theme.swift`'s `Palette` is built entirely on `Color.adaptive(light:dark:)` (e.g. `background`, `primarySurface`, `secondarySurface`, `elevatedSurface`, `border`, `primaryText`, `secondaryText`, `mutedText`, all `Theme.swift:50-58`) — a full second set of hex values, maintained as "the single source of truth," that no build of this app can ever render. A user who sets iOS to Light Mode (for higher perceived contrast, an accessibility reason as much as a preference) gets overridden with no in-app way back. Worth an explicit decision either way: commit to dark-only and delete the light halves of every `Color.adaptive` call (a real simplification — the light hex values are dead weight), or respect `Appearance` and let the light palette do the job it was written for.

## Per flow

### Tasks Home (`Features/Tasks/TasksHomeView.swift` + `TaskRow.swift`)

Large title, `[Ask][Search][…]` trailing toolbar, one header row (ownership tabs, roster-conditional, + a filter control that names its own state), a `ParkedCapturesRow` when anything is unfinished, then status-sectioned rows. No dividers; row height carries rhythm. This is the single mounted surface — there is no tab bar (`RootTabView` confirms: `TasksHomeView()` alone in a `ZStack` with the capture orb, no `TabView` anywhere).

1. **[drift]** The row's primary gesture uses `.onTapGesture` with no default press feedback — see Cross-cutting. `TaskRow.swift:155`.
2. **[polish]** The header row's filter `Menu` names its own state well ("☰ Done", "☰ 2 filters" — `TasksHomeView.swift:372-401`) and clears both filter axes from inside the menu without walking back to "All" twice; genuinely good design-system discipline, worth noting as a positive rather than only citing failures elsewhere.
3. **[polish]** `SignalMarker` reserves its column even when empty (`TaskRow.swift:108`, `reservesSpace: true`) and the due label only renders on live, dated rows (`TaskRow.swift:139`) — both are the kind of small honesty this review is told to reward when found.

### Capture / Ramble (`Features/Capture/ComposerView.swift`, `RambleOrb.swift`, `ConfirmCreationCard.swift`)

Sheet opens directly into a listening orb (no typed field first); silence auto-submits, a tap on the orb finishes early, "Type instead" is the escape hatch to a canvas. On parse, a confirm card reveals editable draft chips; Create dismisses immediately with no receipt screen.

1. No blocking or drift findings distinct from the cross-cutting items — this flow is unusually well-instrumented against its own past mistakes (explicit `.animation(nil)` guards against empty↔non-empty button cross-fades, `GeometryReader`-sized orb rather than an unbounded `maxHeight: .infinity` that previously hung layout, orb `.accessibilityHidden(true)` only once explicit VoiceOver controls exist alongside it). Confirm-card interactions (`ConfirmCreationCard.swift`) are all real `Button`s — no `onTapGesture` substitutions found here despite the surface's density (duplicate/child/date/effort pickers).
2. **[polish]** `ComposerView.swift:295`'s `.onTapGesture { focused = false }` on the background canvas is a legitimate, HIG-normal use of the gesture (dismiss keyboard by tapping empty space, not a disguised button) — flagged here only to distinguish it from the anti-pattern named in Cross-cutting, not as a finding against it.

### Task Detail (`Features/Detail/TaskDetailPager.swift`, `TaskDetailView.swift`)

Full-screen `NavigationStack` cover: custom back chevron, an "n of N" counter, a horizontally-paged `LazyHStack` of task pages with a 20pt leading edge-swipe-back catcher layered over the paging `ScrollView`.

1. No findings. The edge-swipe width (20pt, `TaskDetailPager.swift:273`) is a deliberate, commented trade-off between the OS back-gesture affordance and the horizontal paging gesture, not an under-target control — it's a swipe-catch zone, not a discrete tap target, and it sits at the value iOS's own interactive-pop zone uses. `NavigationStack` here is the root of its own stack (presented via a cover), so the custom chevron is a genuine dismiss control, not a hidden system back button — no `navigationBarBackButtonHidden` misuse. VoiceOver gets explicit `.accessibilityAction`s for paging since a scroll-paging gesture isn't a VoiceOver-navigable swipe (`TaskDetailPager.swift:229-230`). This is the strongest-engineered flow in the app.

### Settings (`Features/Settings/SettingsView.swift`)

Profile card, a three-sentence "what leaves this device" card, data export + two tiered destructive clears (one `confirmationDialog` driven by an enum scope), and a `#if DEBUG`-only diagnostics card.

1. No findings. Destructive actions use `role: .destructive` with a single shared confirmation dialog; every tappable text row takes `LayoutMetrics.hitTarget` as a floor; the diagnostics card's dozen internal metric lines are correctly compiled out of Release builds.

### Activity (`Features/Activity/ActivityView.swift`)

A `List` of change-log rows (avatar + action badge + summary + byline), unread dot, inline Undo, swipe-to-undo as a secondary path.

1. **[drift]** Row tap uses `.onTapGesture` (`ActivityView.swift:174`) — see Cross-cutting.
2. **[drift]** The row's action badge uses an un-scaled 8pt literal font size inside a fixed 14×14 frame (`ActivityRow.swift:150`) — see Cross-cutting.

## Systems lens

The design-token layer (`Design/Theme.swift`, `Typography.swift`, `Motion.swift`, `Glass.swift`, `LayoutMetrics.swift`) is genuinely a system, not a patch collection — nearly every view routes color through `Palette`, spacing through `Spacing`, and glass through the one `.glassChrome` seam, and the codebase's own comments show real self-correction in progress (the `IconSize` doc explicitly narrates its own past mistake: raw point sizes that didn't scale, fixed by adding `Font.glyph*`). That makes the two places where views still reach past the tokens more notable, not less: the sub-caption badge glyphs in `ActivityRow`/`DetailActivityTimeline` are hardcoded in exactly the shape `Typography.swift` documents as the previously-fixed mistake, which means the fix didn't reach every call site it was meant for, not that the rule doesn't exist. Likewise the `.onTapGesture`-as-button pattern across `TaskRow`/`TaskCardView`/`ActivityView` is a missing shared primitive: three independent hand-rolled implementations of "a row that opens something, with a long-press for a secondary menu," each re-deriving the same `.contentShape` + gesture-sensor + accessibility-trait dance. A single `TappableRow` (or a `ButtonStyle` that composes with the existing `contextMenu`/`onLongPressGesture` combination) would collapse three copies into one and get default press feedback for free, which is precisely the "three copies of one card layout means a missing concept" case this lens exists to catch. The Motion token file's dead Today-sequence block is the same failure at the system-maintenance level rather than the call-site level: a "source of truth" file is only true while every removal on the product side is mirrored on the token side, and this audit found one place where that mirroring lapsed. None of these are structural rot — the system is real, actively enforced by comments and by files like `IconSize` that exist purely to fix a previous version of the same mistake — they are the boundary of where that enforcement currently reaches.

## Top fixes

1. **Row tap targets built on `.onTapGesture` instead of `Button`** — `Features/Tasks/TaskRow.swift:155`, `Features/Components/TaskCardView.swift:177-179`, `Features/Activity/ActivityView.swift:174`. Severity: **drift**. Replace with a shared tappable-row primitive (or `Button` + `.buttonStyle(.plain)` composed with the existing long-press/context-menu sensor) so the app's most common gesture gets the same touch-acknowledgment `PressableStyle` guarantees everywhere else.
2. **Un-scaled literal font sizes on action badges, duplicated across two files** — `Features/Components/ActivityRow.swift:150`, `Features/Detail/DetailActivityTimeline.swift:138`. Severity: **drift**. Route through `Font.glyphMicro`/`Font.glyphNano` per `Typography.swift`'s own stated rule, and extract the shared avatar-plus-badge composition into one component.
3. **Dead Motion tokens from the cut Brief still live in the shared design-token file** — `Design/Motion.swift:44-62,251-258` (`capsuleExpand`, `planLanding`, `briefingReveal`, `countUp`, `beatRecede`). Severity: **drift**. Delete alongside the rest of the named Brief-code-removal follow-up, or fold into it now since the tokens are pure deletions with zero call sites.
4. **Forced dark mode leaves a fully-maintained light `Palette` unreachable** — `Project_EzraApp.swift:162` vs. `Design/Theme.swift:50-58`. Severity: **polish**. Deliberate per its own comment, but worth a stated decision: either delete the light half of every `Color.adaptive` call as dead weight, or wire `Appearance` through so the palette that was built actually ships.
5. **No fifth cross-cutting or blocking finding survived verification** — the remaining flows (Capture, Task Detail, Settings) were read in full and came back clean or better-than-average against this review's own checklist; see Per flow above for what specifically holds up.
